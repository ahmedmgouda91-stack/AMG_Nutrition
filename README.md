## الاستخدام بالعربي

افتح `index.html` مباشرة في متصفح حديث؛ الملف مستقل ويعمل بدون إنترنت. النسخة المنفصلة `AMG_Nutrition.html` هي نفس التطبيق. لا تحتاج تثبيت مكتبات أو تشغيل سيرفر للاستعمال المحلي.

1. اختار أو أضف Profile ذكر/أنثى من القائمة. افتح **بيانات وأهداف المستخدم** وأدخل بياناتك؛ بيانات الجسم تبدأ فارغة.
2. احفظ البيانات واعرض **محرك الأهداف**. الأنظمة الستة ونسب العجز الخمسة المعتمدة موجودة، مع Overrides اختيارية. النسب تُكتب 33 عشان 33%.
3. افتح **مخطط الأسبوع** بين محرك الأهداف ومكتبة الأكلات. اختار بداية ونهاية أسبوع من ٧ أيام، وحدد أيام الجيم والراحة بالضغط على التقويم. اضغط **توليد الخطة**؛ عدد أيام الجيم يدخل في حساب النشاط وتتحفظ الأهداف والوجبات والحصص لكل يوم. مركز المتابعة بياخد نوع اليوم من الجدول، بدون اختيار يومي يدوي. راجع الفروق المتبقية قبل اعتماد الأكل الفعلي.
4. افتح وصفة، اختار صحية/تقليدية والكمية، وأضفها للمخطط أو الفعلي. المخطط لا يُحسب أكلاً فعليًا. زر ✓ يفتح تأكيد الكمية المأكولة؛ تقدر تسجل بديل مختلف تمامًا.
5. أضف أكلة غير موجودة من **أكلاتي ووصفاتي**: اسم، كمية مرجعية، وحدة، سعرات، بروتين، دهون وكارب، وحالة/مصدر القيم. القيم كلها تخص نفس الكمية المرجعية. القيم صفر مقبولة؛ الخانات الفارغة غير مقبولة.
6. استخدم **تكوين وصفة** لدمج المكونات أو أكلاتك المحفوظة وتحديد عدد الحصص. بيانات المكونات تُحفظ وقت تكوين الوصفة؛ تعديل المصدر لاحقًا لا يغيّرها تلقائيًا.
7. لتفعيل Real TDEE، سجّل متوسطات وزن يفصلها ٧ أيام ومتوسط الأكل الفعلي اليومي لنفس الفترة. الاختيار الهجين يستخدم النظري لحين الوصول لعدد الأسابيع الصالحة، ثم متوسط آخر N أسابيع صالحة.
8. افتح **قائمة المشتريات** لعرض مقادير الأسبوع من المخطط في ٣ أعمدة فقط: الصنف، الكمية، الوحدة. المكونات المتكررة مجمعة، والكميات قبل طهي الوصفات. السوائل بالمل أو اللتر، والمواد الصلبة بالجرام، مع عرض اختياري بالعدد عند توفر وزن الوحدة. الأكلات الخاصة بدون تفصيل مكونات تظهر كبند جاهز. القائمة قابلة للطباعة.
9. صدّر نسخة شخصية من **عن التطبيق والنسخ الاحتياطي** قبل الانتقال لمتصفح أو جهاز آخر. الاسترجاع يستبدل كل البيانات المحلية بعد تأكيدك.

السجل والمخطط والأهداف والأكلات المخصصة والمفضلة مستقلة لكل مستخدم. الـProfiles فصل محلي للبيانات، وليست حسابات محمية بكلمات مرور. لا توجد مزامنة سحابية أو اتصال بـAMG Core. لا ترفع النسخ الاحتياطية الشخصية إلى مستودع GitHub.

## English quick start

Open `index.html` directly in a modern browser, or use the identical standalone `AMG_Nutrition.html`. No build, installation, account or network connection is required for local use.

Create a Male/Female profile, complete Profile Inputs, save and review Targets Engine. Open Week Planner (between Targets Engine and Meals Atlas), select an inclusive 7-day date range, and mark Gym/Rest days. Generate Plan uses this gym-day count in Targets Engine, selects breakfast/lunch/dinner/snack recipes and optimizes their portions. Command Center reads day types from the saved schedule. Review any remaining macro differences. Regeneration replaces planned meals only; actual intake remains unchanged. Weekly Shopping List aggregates raw ingredients in exactly three columns: item, quantity, unit. It can be printed. Optional piece display uses edible-weight equivalents; custom foods without ingredients are listed as ready-made items. Open any recipe/fruit/custom food and add its quantity to the plan or actual intake. Planned food is never automatically marked as eaten. Each day saves a target snapshot; later input changes do not rewrite historical targets. Explicit refresh updates the selected day only.

Custom foods require a reference quantity, unit, all four nutrition values and a basis/source note. All values apply to that exact reference quantity. Personal recipes combine raw ingredient records or saved user foods and yield a per-serving result. Recipe components and log entries are snapshots. Profile records stay separate and persist in this browser where storage is supported. Export/import a private backup to move devices. Restore replaces all local profiles after confirmation. There is no cloud sync, password protection, telemetry or connection to AMG Core.

## GitHub / GitHub Pages

Upload the **contents** of this folder to the repository root: `index.html`, `assets/`, `manifest.webmanifest`, `sw.js` and the remaining source/documentation folders. A built index is already included. In repository **Settings → Pages**, choose **Deploy from a branch → main → /(root) → Save**. Use the branch you actually uploaded to if different. Publication visibility is controlled by GitHub; this package does not publish anything.

ارفع محتويات المجلد لجذر المستودع، ثم **Settings → Pages → Deploy from a branch → main → /(root) → Save**. التطبيق جاهز بدون Build. الحزمة لا تنشئ مستودعًا ولا تنشره تلقائيًا.

Official guide: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

On HTTPS, the included service worker caches the app after a successful first visit. Reopen once while connected before relying on hosted offline access. Browser installation support varies; if no Install option is offered, use the browser or add a home-screen shortcut. Standalone local HTML does not use a service worker. When updating hosted files, change the cache version in `sw.js`. On first deployment the directory containing `sw.js` is its scope; paths support GitHub Pages project subdirectories.

## Build and test

Only needed to change source code or data. Python 3 builds the self-contained HTML using the standard library:

```sh
python3 tools/build.py
node tests/engine.test.cjs
node tests/week-planner.test.cjs
```

Optional browser tests require Playwright and a Chromium executable in your own development environment:

```sh
PLAYWRIGHT_MODULE=playwright CHROMIUM_PATH=/path/to/chromium node tests/browser.test.cjs
PLAYWRIGHT_MODULE=playwright CHROMIUM_PATH=/path/to/chromium node tests/hosted.test.cjs
```

The browser tests use synthetic profile data in an isolated browser context, never saved into the delivered HTML. Screenshots are internal test output in a sibling `amg_nutrition` directory. Reports contain results only. `src/engine.js` owns all target calculations; `src/planner.js` owns portion matching and grocery aggregation; `src/planner-ui.js` owns the weekly calendar and shopping interface; `src/app.js` owns the UI, profile storage and logging. `data/nutrition-data.json` is public catalog data, separate from personal state. To deploy, no Node or Python installation is required.

Modern Chrome, Edge, Safari and Firefox support the main app features. File downloads and local-file persistence depend on browser/device settings. If a phone preview does not execute HTML, open the downloaded file in a browser or use your GitHub Pages deployment. Keep regular backups, especially for local files and private browsing.
